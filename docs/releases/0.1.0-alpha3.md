# 0.1.0-alpha3

Third alpha of the Unified API for Vaadin UI tests. It changes the shape of a lookup ([ADR 0007](https://github.com/parttio/unified-testing-tool/blob/main/docs/adr/0007-wrappers-carry-their-filters.md)):
the Wrapper carries its filters and `single()` is gone. It also makes tests and their failures readable: every test
records its User Steps, failures name the Near Misses, and a run writes a summary and an HTML report.

The API can still change between alphas. **Every existing Unified UI Test needs changes**; see **Breaking changes**.

## Get it

On Maven Central as `org.vaadin.addons:*:0.1.0-alpha3`. Import `unified-test-bom` and add the adapters you
run on as test dependencies (see [Try it](https://parttio.github.io/unified-testing-tool/#try-it)).

Requires Java 21, Vaadin 25.3 and, for `@UnifiedSpringBootTest`, Spring Boot 4.1. The Playwright adapter uses
Dramafinder 2.2.0.

## Breaking changes

- **Wrappers carry their filters; `single()` is gone** ([#245](https://github.com/parttio/unified-testing-tool/pull/245),
  [ADR 0007](https://github.com/parttio/unified-testing-tool/blob/main/docs/adr/0007-wrappers-carry-their-filters.md)). `page.find(..)` returns the Wrapper, and filters return a
  new Wrapper. Each use checks again for exactly one match, within the Auto-Wait timeout.
  ```diff
  -page.find(UnifiedTextField.class).withLabel("Name").single().setValue("Alan M. Turing");
  -people.rows().withCellText("Name", "Alan Turing").single().click();
  -assertEquals(11, users.rows().withCellTextContaining("Email", "user11").all().size());
  +page.find(UnifiedTextField.class).withLabel("Name").setValue("Alan M. Turing");
  +people.row().withCellText("Name", "Alan Turing").click();
  +assertThat(users.row().withCellTextContaining("Email", "user11")).hasCount(11);
  ```
  The per-type query classes, the boolean `exists()` and `rows()` are gone. Use `assertThat(..).exists()`,
  `.doesNotExist()` and `.hasCount(n)`; `all()` stays for iterating; `row(n)` takes an index. Grid row actions now
  get Auto-Wait ([#214](https://github.com/parttio/unified-testing-tool/issues/214)).
- **`withClassName` takes one class; `withClassNames(..)` takes several**, as in Flow
  ([#261](https://github.com/parttio/unified-testing-tool/pull/261)). `withClassName("a b")` throws
  `IllegalArgumentException` on every tool. It used to match on Browserless and never in a browser.
- **The adapter SPI is Test Runner-neutral** ([ADR 0008](https://github.com/parttio/unified-testing-tool/blob/main/docs/adr/0008-adapter-spi-is-test-runner-neutral.md),
  [#243](https://github.com/parttio/unified-testing-tool/pull/243), [#244](https://github.com/parttio/unified-testing-tool/pull/244),
  [#248](https://github.com/parttio/unified-testing-tool/pull/248)). `extensionContext()` is gone; adapters get an
  `AdapterContext`. `AdapterSession.settle()` is new, with a no-op default. Only custom adapters are affected.
- **JUnit is optional in `unified-test-api`** ([#249](https://github.com/parttio/unified-testing-tool/pull/249)).
  A JUnit test brings its own `junit-jupiter-api`. `unified-test-spring` still depends on it.
- Every Unified failure is a `UnifiedAssertionError` (an `AssertionError`) with a new message layout
  ([#253](https://github.com/parttio/unified-testing-tool/pull/253)). Update any test that matches the old message text.

## New

- **User Steps** ([#247](https://github.com/parttio/unified-testing-tool/pull/247)): every test records what the user
  did on every tool. `page.step("Edit Alan Turing", () -> ..)` groups actions into named, nested steps. The steps
  go to the log, to `user-steps.txt` / `user-steps.json` per test, and into a failure.
- **Failure messages with Near Misses** ([#253](https://github.com/parttio/unified-testing-tool/pull/253)): the
  failed User Step, what was expected and found, the components nearby and, when one is clearly best, a
  `Did you mean` call. They read the same on every tool.
  ```text
  Expected      exactly one text field labelled “Email”
  Found         none
  Nearby        text field “E-mail”, text field “Name”
  Did you mean  find(UnifiedTextField.class).withLabel("E-mail")
  ```
- **Run reports** ([#250](https://github.com/parttio/unified-testing-tool/pull/250),
  [#265](https://github.com/parttio/unified-testing-tool/pull/265), [#270](https://github.com/parttio/unified-testing-tool/pull/270),
  [#279](https://github.com/parttio/unified-testing-tool/pull/279)): `summary.md` and `report.html` at the end of a
  run, with "Changed in this PR" (scenarios that call code changed since the base ref, diffed against the base
  run). In GitHub Actions the summary goes to the job summary. See "Running in CI" in the guide
  ([#266](https://github.com/parttio/unified-testing-tool/pull/266)).
- **Evidence per User Step**, opt-in ([#271](https://github.com/parttio/unified-testing-tool/pull/271)):
  `vaadin.testing.user-steps.snapshots=true` writes a screenshot (browsers) or a component tree (Browserless)
  after every step. `vaadin.testing.playwright.trace=on-failure` (or `on`) keeps Playwright's trace as
  `trace.zip`, grouped by User Step. `page.secret(..)` masks a value in the steps and text snapshots.
- **`unified-test-archunit`** ([#252](https://github.com/parttio/unified-testing-tool/pull/252)), in the BOM:
  `UnifiedStyleRules` checks the Unified UI Test style (a sentence per scenario, no raw waits, tool-specific code
  only behind `@RequiresTestingTool`). See [Checking the style](https://parttio.github.io/unified-testing-tool/guide/style-rules/).
- **Item Names** for tabs and menu items on every tool: the item's text, or its `aria-label` when it shows none.
  New: `UnifiedMenuBar.isItemEnabled(..)` and `UnifiedDateTimePicker.typeText(..)`
  ([#109](https://github.com/parttio/unified-testing-tool/pull/109)).
- **`withLabel` matches a FormLayout item's label** (`addFormItem(field, "Nickname")`) on every tool
  ([#276](https://github.com/parttio/unified-testing-tool/pull/276)).
- **Developer guide** on the documentation site ([#136](https://github.com/parttio/unified-testing-tool/pull/136)),
  rewritten for ADR 0007 ([#254](https://github.com/parttio/unified-testing-tool/pull/254)), and the guides
  "Migrating from TestBench", "Migrating from Browserless" and "Migrating from Dramafinder".
- **Migration Recipes and agent skills, in the repository** (`unified-test-rewrite`, not on Maven Central before
  `spec-v1`): OpenRewrite recipes from TestBench, Browserless and Dramafinder tests, the
  `resolve-migration-markers` skill for what they can't convert, and the `write-unified-ui-tests` skill
  ([#257](https://github.com/parttio/unified-testing-tool/pull/257)). Escape Hatches for migrated code:
  `TestBenchEscapeHatch` and `BrowserlessEscapeHatch`.

## Fixed

- Auto-Wait waits for the address bar after a server-side navigation, so the URL read right after a click is the
  new one ([#262](https://github.com/parttio/unified-testing-tool/pull/262)).
- `getText()` and `withText` leave out a tooltip's text in a browser, as on Browserless
  ([#268](https://github.com/parttio/unified-testing-tool/pull/268)).
- Browserless reads a whole-number property as the browsers do (`"3"`, not `"3.0"`)
  ([#260](https://github.com/parttio/unified-testing-tool/pull/260)).
- Playwright queries leave out Copilot's and Vaadin's shadow DOM, so Copilot's toolbar no longer matches
  ([#191](https://github.com/parttio/unified-testing-tool/pull/191)).
- Playwright: a combo box's `getItems()` returns every item, not only the first page (Dramafinder 2.0.2,
  [#128](https://github.com/parttio/unified-testing-tool/pull/128)).
- The Playwright and Selenium adapters use Dramafinder's and TestBench's APIs instead of their own scripts
  ([#128](https://github.com/parttio/unified-testing-tool/pull/128), [#171](https://github.com/parttio/unified-testing-tool/pull/171),
  [#183](https://github.com/parttio/unified-testing-tool/pull/183), [#256](https://github.com/parttio/unified-testing-tool/pull/256),
  [#269](https://github.com/parttio/unified-testing-tool/pull/269)). Dramafinder 2.2.0 also keeps checkbox clicks
  and `vaadin-select`'s `aria-label` working on Vaadin 25.4.

## Known limitations

- Browserless: searching inside Grid row details (`row.details()`) throws; toggling and checking details works.
- Browserless: `page.reload()`, `pressKey` and `dispatchEvent` are simulated; client-side behaviour (typing text,
  Tab moving focus) doesn't happen ([#66](https://github.com/parttio/unified-testing-tool/issues/66)).
- Browserless: deselecting one item of a MultiSelectComboBox is done on the server, not as from the client
  ([#61](https://github.com/parttio/unified-testing-tool/issues/61)).
- A component that was never visible is in no browser's page but Browserless finds it; `.visible()` gives the
  same answer everywhere ([#97](https://github.com/parttio/unified-testing-tool/issues/97)).
- Selenium: a combo box's `getItems()` returns the drop-down's first page only (50 items by default)
  ([#127](https://github.com/parttio/unified-testing-tool/issues/127)).
