# 0.1.0-alpha4

Fourth alpha of the Unified API for Vaadin UI tests. Its theme is the loop of someone, or an agent, writing and
fixing tests: the run as data, what a passing test fails to check, where two Testing Tools disagree, what the
application logged, and a repair for a renamed label. It also takes in the feedback from migrating a 205-test
Browserless suite with 0.1.0-alpha3 ([#375](https://github.com/parttio/unified-testing-tool/issues/375)), and makes the Unified layer cheaper on every Testing Tool.

The API can still change between alphas. **No existing Unified UI Test needs changes**; a run behaves differently in
the ways under **Changed behaviour**. A custom adapter must adopt the new evidence SPI (see **Adapters** there).

## Get it

On Maven Central as `org.vaadin.addons:*:0.1.0-alpha4`. Import `unified-test-bom` and add the adapters you
run on as test dependencies (see [Try it](https://parttio.github.io/unified-testing-tool/#try-it)).

Requires Java 21, Vaadin 25.3 and, for `@UnifiedSpringBootTest`, Spring Boot 4.1. The Playwright adapter uses
Dramafinder 2.2.1. Browserless Test and TestBench now come at the versions your Vaadin BOM manages.

## Changed behaviour

- **Vaadin's development tools are off in a `@UnifiedSpringBootTest`'s application**
  ([#317](https://github.com/parttio/unified-testing-tool/pull/317)): `vaadin.devmode.devTools.enabled=false`, as
  the last property source, so anything else that sets it wins. In development mode Vaadin Copilot starts file
  watchers for every browser session and keeps them until the application stops
  ([#318](https://github.com/parttio/unified-testing-tool/issues/318)); a run of some 64 browser tests reached
  the usual Linux limit, and every session after that logged an error. A test that needs the tools sets the
  property to `true`.
- **`user-steps.txt` can have more lines** ([#314](https://github.com/parttio/unified-testing-tool/pull/314)): the
  application's warnings and errors, and the browser console's errors, show under the User Step during which they
  were logged. `vaadin.testing.user-steps.server-log=off` turns the application's lines off.
- **`hasSelectedItems(..)` names its items in the test's order**
  ([#309](https://github.com/parttio/unified-testing-tool/pull/309)). The order used to change from one JVM to
  the next, so the same scenario worded its User Step differently in two runs. A Base Run recorded before this
  can show one changed line for a scenario that uses it, once.
- **Every run asks git for its commit** ([#312](https://github.com/parttio/unified-testing-tool/pull/312)): two
  calls when the run ends, for `summary.json`. Without git the fields are left out.
- **Playwright downloads only the browser a run launches**
  ([#299](https://github.com/parttio/unified-testing-tool/pull/299),
  [#337](https://github.com/parttio/unified-testing-tool/issues/337)). `Playwright.create()` used to download every
  browser it supports, some 1.3 GB, though a run opens one. Now the run installs the browser of
  `vaadin.testing.playwright.browser`, with Playwright's `install` command: for headless Chromium, the default,
  Chromium's headless shell, about 280 MB. With `vaadin.testing.playwright.executable` set it downloads nothing,
  and `PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1` is no longer needed beside the executable. The environment still has
  the last word: with `PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD` or `SELENIUM_REMOTE_URL` set, the run installs nothing.
  Playwright decides its own download at the JVM's first `Playwright.create()`, so code that creates a `Playwright`
  before the first test still downloads everything. A CI step that ran `install --with-deps chromium` before the
  tests can run `install-deps chromium` instead, for the system libraries only.
- **`AddUnifiedTestingSkill` writes its pointer to `CLAUDE.md` when a project has no `AGENTS.md`**
  ([#365](https://github.com/parttio/unified-testing-tool/issues/365)). Claude Code reads `CLAUDE.md`, not
  `AGENTS.md`, so the marked section goes at the end of the existing `CLAUDE.md`, and no `AGENTS.md` is created.
  The rest of `CLAUDE.md` is left as it is. A project with both files, or with neither, gets the section in
  `AGENTS.md`, as before.
- **Chrome on Selenium is started with a logging capability**
  ([#315](https://github.com/parttio/unified-testing-tool/pull/315)), and its console is read after every User
  Step.
- **A failed test writes one more evidence file**, `<test>.view.txt`, the Findable View below, and the failure's
  `Failure evidence` line names it. Writing it makes about 20 lookups, on failure only. It is written even when
  the screenshot can't be.
- **`Scope` has a new method, `describe()`.** The Unified API implements it for the page and for every Wrapper
  that is a Scope, custom ones included. Only a class of your own that implements `Scope` must add it.
- **`unified-test-bom` no longer sets Browserless Test's version**
  ([#387](https://github.com/parttio/unified-testing-tool/issues/387)): `browserless-test-junit6` and
  `browserless-test-spring` come at the version the project's Vaadin BOM manages, as TestBench always did. With
  `unified-test-bom` imported before the Vaadin BOM, a project ran on 25.3.2; it now runs on its Vaadin's
  Browserless Test, also 25.3.2 on Vaadin 25.3.5. The BOM still sets Dramafinder's version.
- **A test on a Vaadin older than 25.3 fails at once**
  ([#387](https://github.com/parttio/unified-testing-tool/issues/387)), with a message that names the version it
  found, before its Spring context starts. It used to fail later, with an error from Browserless Test or Flow that
  didn't say why. A test without Flow on its classpath is not checked.
- **The Migration Recipes leave a Migration Marker at the top of `pom.xml`** on a project older than Vaadin 25.3
  ([#387](https://github.com/parttio/unified-testing-tool/issues/387)), and migrate it all the same.
- **The Dramafinder recipe marks the test classes it skips** ([#350](https://github.com/parttio/unified-testing-tool/issues/350)):
  a class that uses a base class member no rule converts gets a Migration Marker above it, naming those members
  (`not migrated: calls loginAs(..) of SpringPlaywrightIT, uses chatModel of SpringPlaywrightIT; ...`). Such a
  class used to stay unchanged, with nothing saying why. A `setupTest()` override that seeds data and then calls
  `super.setupTest()` no longer keeps a class from migrating: it becomes a plain `@BeforeEach`, without the
  `super.setupTest()`, since each test now navigates itself. Nor do the members of a project's copy of
  `SpringPlaywrightIT`: each migrated test gets the copy's fields and helpers it uses, and its `@BeforeEach`,
  `@AfterEach` and `@RegisterExtension` members, as its own. A member that uses the test base where no rule
  converts it (an extension reading `page`, an override of `setupTest()`) still keeps the test from migrating.
- **The Dramafinder recipe navigates by route class** ([#370](https://github.com/parttio/unified-testing-tool/issues/370)):
  a `getView()` returning `"/plan"` now starts each test with `page.navigate(PlanView.class)`, when exactly one
  `@Route("plan")` is among the migrated sources, where it used to write `page.navigate("/plan")`. A renamed route
  then breaks at compile time, and the User Step reads `open Plan`. With no such view, several, or one under a
  layout with a `@RoutePrefix`, the path stays.
- **The Browserless recipe marks per-class `@ServiceConnection` fields** ([#331](https://github.com/parttio/unified-testing-tool/issues/331)):
  when several migrated classes declare their own, each field gets a Migration Marker (`one Spring context per
  class: 3 test classes (...) declare their own @ServiceConnection field, ...`). Each such class starts its own
  Spring context and, with `@UnifiedSpringBootTest`, its own embedded server, on Browserless too; one suite ran
  54 % slower after the migration for that reason. The guide and the `write-unified-ui-tests` skill now recommend
  one shared base class ([One Spring context](../migrating-from-browserless.md#one-spring-context)).
- **`@RequiresTestingTool` and `@RequiresBrowser` are inherited** ([#327](https://github.com/parttio/unified-testing-tool/issues/327)): a test class that extends a
  Browserless-only base class is skipped on the browser Testing Tools, as its base is. It used to run there, and a
  `@Transactional` base failed it with `@Transactional on ... doesn't work on PLAYWRIGHT`.
- **On Browserless, setting a checkbox clears its indeterminate state** ([#328](https://github.com/parttio/unified-testing-tool/issues/328)), as a user's click does in a
  browser.
- **Browserless leftovers name the Core Set Wrapper** ([#325](https://github.com/parttio/unified-testing-tool/issues/325)): a Migration Marker for a component the recipe
  doesn't convert says `X has a Core Set Wrapper: use UnifiedX`, or `X extends Y: use UnifiedY with a filter`,
  where it used to say `no Wrapper for X: write one (ADR 0003)` for components such as `MenuBar` or a `Dialog`
  subclass.
- **Dramafinder 2.2.1** ([#448](https://github.com/parttio/unified-testing-tool/issues/448)): `unified-test-bom` manages Dramafinder 2.2.1, and the Playwright adapter
  reads grid captions and text through it, where it had its own scripts. Dramafinder 2.2.1's idle wait makes one
  more browser call, so every Playwright step that waits costs one call more, on the Unified API and on Dramafinder
  alike, until Dramafinder's wait is one call again.
- **On Playwright, a step that loads a whole page waits until Flow has started it** ([#397](https://github.com/parttio/unified-testing-tool/issues/397)): after a link out of
  the router, a login form's POST or `Page.setLocation`, Auto-Wait waits for `load`, then until Flow has
  registered its UI (at most 5 s: a Hilla view never does), then for the round trip. A navigation that `Page.setLocation`
  starts after Flow is idle is waited for too.
- **In `report.html`, a step's screenshot opens in a viewer** ([#472](https://github.com/parttio/unified-testing-tool/issues/472)), over the report, instead of under the
  step; see **New**.
- **Adapters:** `AdapterSession` has new methods with a default, `consoleErrors()`, `title()` and
  `navigate(view, parameters, query)`. An adapter outside this repository keeps compiling; its `hasTitle(..)` fails
  until it implements `title()`, and its navigation with query parameters opens the path the annotations give.
  `SelectionAccess.trySelect(label)` (default `false`) and the optional `UsabilityCheck` let an adapter pick an item
  or check an element in fewer calls; without them the core does as before. `writeStepSnapshot(..)` and
  `writeFailureEvidence(..)` take the Step Target and return `Evidence` ([#472](https://github.com/parttio/unified-testing-tool/issues/472)): **an adapter
  outside this repository no longer compiles** until it adopts the new signatures.

## New

- **`summary.json`: the run as data** ([#306](https://github.com/parttio/unified-testing-tool/pull/306)), next to
  `summary.md` and `report.html`: the verdict and the counts, the commit, then every scenario with the paths to
  its files. A failed scenario carries the `failure` object of its `user-steps.json`; a scenario under "Changed
  in this PR" says why. See [The run as data](https://parttio.github.io/unified-testing-tool/guide/reports-and-failures/#the-run-as-data).
- **Scenarios without a check** ([#307](https://github.com/parttio/unified-testing-tool/pull/307)): the run summary
  lists the passing scenarios that end on User Steps nothing checks.
  ```markdown
  #### Scenarios without a check

  - **Saving a person closes the dialog (EditPersonTest)** · no check after: `click button “Save”`
  ```
  A retrying assertion is a check; so is a value the test reads after its last action, which the recorder now
  counts (`readsAfter` in `user-steps.json`). It reports and fails no test.
- **Compared with another Testing Tool** ([#309](https://github.com/parttio/unified-testing-tool/pull/309),
  [#312](https://github.com/parttio/unified-testing-tool/pull/312)): give a run the evidence directory of a run on
  another Testing Tool (`vaadin.testing.user-steps.compare-dir`), and its summary says which scenarios pass on one
  and fail on the other, which take different User Steps and where they part, and whether both runs tested the
  same code. In CI, where each Testing Tool has its own job, the `CompareRuns` command does the same from the
  jobs' evidence; see [Running in CI](https://parttio.github.io/unified-testing-tool/guide/ci-setup/#comparing-the-testing-tools-runs).
  ```
  mvn test -Dvaadin.testing.evidence-dir=target/evidence-browserless
  mvn test -Dvaadin.testing.tool=playwright \
      -Dvaadin.testing.user-steps.compare-dir=target/evidence-browserless
  ```
- **What the application logged, under the User Step** ([#314](https://github.com/parttio/unified-testing-tool/pull/314),
  [#315](https://github.com/parttio/unified-testing-tool/pull/315)): on every Testing Tool, the application's
  warnings and errors with the logged exception; on Playwright and on Selenium with Chrome, the browser console's
  errors.
  ```text
     3  click button “Save” in dialog “Edit person”
        ⚠ server ERROR PersonService: Could not save Alan Turing (IllegalStateException: no id)
  ```
  Heard through Logback, else `java.util.logging`; nothing to add to a project's build.
- **`assertThat(page).hasNoErrors()`** ([#314](https://github.com/parttio/unified-testing-tool/pull/314)): fails a
  scenario that left an error in the application's log or a browser's console, and lists what. It looks once and
  doesn't wait.
- **`ApplyDidYouMean`** ([#313](https://github.com/parttio/unified-testing-tool/pull/313)), a recipe in
  `unified-test-rewrite`: after a failed run, it writes each failure's `Did you mean` into the test.
  `withLabel("Email")` becomes `withLabel("E-mail")`. No model, nothing at test time: a diff to review. See
  [Applying it](https://parttio.github.io/unified-testing-tool/guide/reports-and-failures/#applying-it).
- **`FindTestClassesToMigrate`** ([#352](https://github.com/parttio/unified-testing-tool/issues/352)), a search
  recipe in `unified-test-rewrite`: run as a dry run before a migration, it marks every TestBench, Browserless and
  Dramafinder test class `migrates` or `skipped: <why>`, and lists them in a data table, so a suite's blockers show
  in one pass instead of one per migration run. See [Which classes it skips](https://parttio.github.io/unified-testing-tool/migrating-from-dramafinder/#which-classes-it-skips).
- **The Findable View** ([#204](https://github.com/parttio/unified-testing-tool/issues/204)): `page.describe()`,
  or `describe()` on a dialog or any other Scope, lists what a test can find there, one line each, with the lookup
  that singles it out. It reads the same on every Testing Tool, and a failed test writes the page's view next to
  its evidence. See [What is there to find?](https://parttio.github.io/unified-testing-tool/guide/finding-components/#what-is-there-to-find)
  ```text
  text field “Name” = “Alan Turing”    page.find(UnifiedTextField.class).withLabel("Name")
  button “Archive” (disabled)          page.find(UnifiedButton.class).withText("Archive")
  button “Delete account”              page.find(UnifiedButton.class).withAccessibleName("Delete account")
  ```
- **`assertThat(page).hasTitle(..)`** ([#360](https://github.com/parttio/unified-testing-tool/issues/360)): the
  page's title, from the view's `@PageTitle`, `HasDynamicTitle` or `Page.setTitle(..)`, on every Testing Tool.
  Browserless reads the title the UI last set; a "page has its title" test no longer needs the Escape Hatch.
  ```java
  assertThat(page).isAt(ProfileView.class).hasTitle("Profile");
  ```
- **Wrappers for a chat** ([#357](https://github.com/parttio/unified-testing-tool/issues/357)):
  `UnifiedMessageInput` and `UnifiedMessageList`, for apps built on Vaadin's AI components. `send(text)` types and
  submits a message; the list's `getMessages()` reads each message's user name and text, the text the application
  gave it (the Markdown source), the same on every Testing Tool. Its checks wait for a reply:
  ```java
  page.find(UnifiedMessageInput.class).send("Pancakes");
  assertThat(page.find(UnifiedMessageList.class)).hasMessageCount(3).hasMessageContaining("Pancakes");
  ```
  See [Chat](https://parttio.github.io/unified-testing-tool/guide/components/#chat). The Migration Recipes convert
  the message elements and testers too: Dramafinder's `typeAndSubmit`, `assertMessageCount` and `assertEmpty`,
  TestBench's `submit` and `getMessageElements().size()`, Browserless's `send` and `size()`.
- **For agents** ([#319](https://github.com/parttio/unified-testing-tool/pull/319)): the `unified-test-api` jar
  ships [`META-INF/unified/api-reference.md`](https://parttio.github.io/unified-testing-tool/api-reference/), every
  Wrapper with its filters, actions, reads and checks, generated from the code. The site has an
  [`llms.txt`](https://parttio.github.io/unified-testing-tool/llms.txt), every page as Markdown and the guide in
  one file.
- **The agent skill reviews tests** ([#410](https://github.com/parttio/unified-testing-tool/issues/410)):
  `write-unified-ui-tests` has a "Review a test" section. Asked to review a test or a pull request's tests, an agent
  compares the scenario with the test's User Steps, the code with the canonical forms, runs it twice on two Testing
  Tools, checks what a change made to pass took away, and reports without changing the code. For people, the same
  checklist is the guide's [Reviewing a test](../guide/reviewing-tests.md).
- **`click()` on `UnifiedDiv`, `UnifiedSpan`, `UnifiedContainer` and the other plain HTML Wrappers**
  ([#358](https://github.com/parttio/unified-testing-tool/issues/358)): a `Div` or `Span` with a click listener,
  such as a navigation tab, or a layout such as a card, is clicked like a button, where a test used to write
  `element().click()`.
  ```java
  page.find(UnifiedDiv.class).withText("Shop").click();
  page.find(UnifiedContainer.class).withTestId("recipe-card").click();
  ```
- **Navigating by route class with query parameters** ([#370](https://github.com/parttio/unified-testing-tool/issues/370)):
  `page.navigate(view, QueryParameters)` and `page.navigate(view, RouteParameters, QueryParameters)`, as Flow's
  `UI.navigate(..)`, on every Testing Tool. A navigation with a query string no longer needs the path form; its User
  Step names the parameters, `open Plan with “week=2026-11-02”`.
  ```java
  page.navigate(PlanView.class, QueryParameters.of("week", "2026-11-02"));
  ```
- **Retrying assertions for a grid's columns** ([#359](https://github.com/parttio/unified-testing-tool/issues/359)):
  `assertThat(grid).hasColumn("Cooked times")`, `doesNotHaveColumn(..)` and `hasColumnHeaders(..)`, for a column
  the application adds or removes while the test runs. They replace `page.waitUntil(() ->
  grid.getColumnHeaders().contains(..))`, a gap in the reports, and fail with the headers the grid has. See
  [Columns](https://parttio.github.io/unified-testing-tool/guide/grid/#columns).
- **The Dramafinder recipe converts raw locators on an id or test id**
  ([#356](https://github.com/parttio/unified-testing-tool/issues/356)): `page.locator("#week-next")`,
  `locator("[data-testid=card]")` and `getByTestId("card")` become `page.find(UnifiedButton.class).withId(..)` or
  `withTestId(..)`, with the Wrapper of the component the application's views set that id on (`setId("..")`,
  `getElement().setAttribute("data-testid", "..")`), and `fill`, `inputValue`, `check` and `click` become the
  Wrapper's calls. So do `assertThat(locator)`'s `isVisible()`, `isEnabled()`, `isDisabled()`, `hasValue(..)` and
  `isChecked()`. An id no view sets becomes a `UnifiedContainer` lookup, which finds any component, with a Migration
  Marker. They used to stay behind the Escape Hatch, one marker each.
- **Retrying assertions for a menu bar's items** ([#330](https://github.com/parttio/unified-testing-tool/issues/330)):
  `assertThat(menu).hasItems("File", "Help")`, `hasItems(List.of("File", "Export"), "PDF", "CSV")` for a
  sub-menu, and `hasItem(..)`, `hasItemEnabled(..)` and `hasItemDisabled(..)`, which take a path like
  `clickItem(..)`. They replace `assertEquals` on `getItems(..)` and `isItemEnabled(..)`, which read once and left
  no `see` line in `user-steps.txt`. See
  [Buttons and menus](https://parttio.github.io/unified-testing-tool/guide/components/#buttons-and-menus).
- **`UnifiedDateTimePicker.typeText(LocalDate, String)`**
  ([#329](https://github.com/parttio/unified-testing-tool/issues/329)): types the date in the field's own format,
  which a browser takes from the field's locale, and the time as it is. A test of incomplete input, a date with no
  time, no longer branches on the Testing Tool: `typeText("2026-07-01", "")` was incomplete input on Browserless
  and bad input in a browser.

- **The Browserless recipe converts the `Locators` mixin** ([#323](https://github.com/parttio/unified-testing-tool/issues/323)): in a class that `implements Locators`,
  `findButton().withAriaLabel("Load")` becomes `page.find(UnifiedButton.class).withAccessibleName("Load")`,
  `findGrid(..).getCellText(row, col)` becomes `page.find(UnifiedGrid.class).row(row).getCellText(col)`, and
  `implements Locators` goes once no mixin call is left. A mixin call with no Wrapper form, and every
  `UI.getCurrent()` or `VaadinSession.getCurrent()`, gets a Migration Marker and
  `@RequiresTestingTool(BROWSERLESS)`, since only Browserless runs the server in the test's JVM.
- **`UnifiedCheckbox.click()` toggles the checkbox on every Testing Tool** ([#328](https://github.com/parttio/unified-testing-tool/issues/328)). In a browser, the generic
  click hit the middle of the component, which for a full-width checkbox (in a FormLayout) is empty space that
  Vaadin ignores. The Browserless recipe now converts a checkbox's `click()` instead of marking it.
- **The Step Target, highlighted in browser screenshots** ([#472](https://github.com/parttio/unified-testing-tool/issues/472),
  [ADR 0010](https://github.com/parttio/unified-testing-tool/blob/main/docs/adr/0010-browser-screenshots-are-highlighted-by-the-report.md)):
  the component a User Step last singled out to act on or check. With `vaadin.testing.user-steps.snapshots=true`,
  `report.html` opens a step's screenshot in a viewer (a filmstrip, ← →, Esc) with everything outside that
  component's box dimmed, and the failure's screenshot shows its spotlight inline. A switch, or `h`, turns the
  spotlight off. The box is recorded as `highlight` in `user-steps.json`, as fractions of the image, or why there is
  none (`gone`, `outside`); the PNG and the page are never changed. On Browserless the step's tree marks the Step
  Target, now for a check too. See [What the page looked like at each step](https://parttio.github.io/unified-testing-tool/guide/reports-and-failures/#what-the-page-looked-like-at-each-step).
- **Readable component trees in `report.html`** ([#391](https://github.com/parttio/unified-testing-tool/issues/391)): a Browserless step's **tree** link opens a foldable
  page under the step, with a search, as a screenshot does, instead of the raw `.tree.txt`.
- **The `resolve-migration-markers` skill covers what a literal conversion changes**
  ([#332](https://github.com/parttio/unified-testing-tool/issues/332)): absence checks need `.visible()`, checkboxes are set rather than clicked, one shared Spring context,
  and a full-suite run on Browserless and Playwright after the per-class runs.
- **Guide pages:** [Getting started](../guide/getting-started.md) now breaks the first test on purpose and reads
  its failure; new [Troubleshooting](../guide/troubleshooting.md), keyed by what the run says,
  [Common mistakes](../guide/common-mistakes.md) as Bad/Good pairs, and
  [Benchmarking the Unified layer](../guide/performance-benchmark.md). The guide's navigation is grouped by what
  the reader is doing.

## Faster

Each user action makes fewer calls to the Testing Tool, measured against the same scenario written for the
Testing Tool directly ([spec 13](../spec/13-performance.md)):

- **Browserless:** one walk of the component tree per lookup, where there were two ([#401](https://github.com/parttio/unified-testing-tool/issues/401)); a row lookup by
  cell text reads a plain grid column in one data-provider fetch, not one per cell ([#443](https://github.com/parttio/unified-testing-tool/issues/443)).
- **Playwright:** Auto-Wait's visible-and-enabled check, `settle()` and a filtered lookup each take one driver
  call ([#402](https://github.com/parttio/unified-testing-tool/issues/402)); a grid column is read in one script, without waiting out the grid connector's 150 ms request
  delay per page ([#446](https://github.com/parttio/unified-testing-tool/issues/446)); `selectItem(..)` on a combo box filters by the label once, not twice ([#445](https://github.com/parttio/unified-testing-tool/issues/445)).
- **Selenium:** a grid column is read in one asynchronous script, where finding row 250 of 500 took 285 commands
  ([#404](https://github.com/parttio/unified-testing-tool/issues/404)); a notification's text is read without TestBench's 500 ms poll during its open animation
  ([#447](https://github.com/parttio/unified-testing-tool/issues/447)).
- **Playwright and Selenium:** `selectItem(..)` on a combo box filters by the label and picks the item, instead of
  reading every item of a lazy drop-down first ([#403](https://github.com/parttio/unified-testing-tool/issues/403)). The failure message is unchanged.

## Fixed

- A run without the adapter of its Testing Tool named the dependency to add as `com.vaadin:unified-test-<tool>`,
  which the alphas aren't published as. It now names `org.vaadin.addons:unified-test-<tool>`
  ([#435](https://github.com/parttio/unified-testing-tool/issues/435)).
- `hasSelectedItems(..)` worded its User Step in an order that changed from run to run
  ([#309](https://github.com/parttio/unified-testing-tool/pull/309)).
- On Browserless, a lookup inside a Scope also found the Scope itself: `dialog.find(UnifiedDialog.class)` found
  the dialog, where a browser finds none ([#333](https://github.com/parttio/unified-testing-tool/issues/333)).
  A grid cell, a column header, and Details and TabSheet content still find the components they hold.
- In a browser, a failure with several matches outside any container named Flow's root as their container,
  `in container (id “ROOT-2521314”)`, an id that changes on every page load and tells none of them apart
  ([#334](https://github.com/parttio/unified-testing-tool/issues/334)). It now reads as on Browserless.
- A `@UnifiedSpringBootTest` application without Spring Security failed to start, with `NoClassDefFoundError:
  org/springframework/security/core/Authentication`
  ([#348](https://github.com/parttio/unified-testing-tool/issues/348)). It now starts without the test login
  endpoint, and `spring-security-core` is no longer needed as a workaround.
- The Migration Recipes ignored the options a project's `rewrite.yml` set: `addAgentSkill`, the adapters,
  `includePageObjects` ([#353](https://github.com/parttio/unified-testing-tool/issues/353)). OpenRewrite matches
  options to a recipe's constructor parameters by name, and `unified-test-rewrite` was compiled without the names,
  so the recipe ran with its defaults and said nothing. It is now compiled with `-parameters`.
- A JUnit 4 test that `@Ignore` skipped ran again after the TestBench or Browserless (UI Unit) Migration Recipe
  ([#386](https://github.com/parttio/unified-testing-tool/issues/386)): `@Test` became JUnit 6's, but `@Ignore`
  stayed JUnit 4's, which JUnit 6 doesn't read. The recipes named OpenRewrite's `IgnoreToDisabled`, a declarative
  recipe in another jar that they never loaded, and the plugin logged a validation error. `@Ignore` now becomes
  `@Disabled`.
- The Dramafinder recipe dropped the class annotations of a project's copy of `SpringPlaywrightIT`: a test that
  extended it lost `@ActiveProfiles`, `@Import` and `@SpringBootTest(properties = ..)`, and ran against the
  default profile without a marker ([#349](https://github.com/parttio/unified-testing-tool/issues/349)). Each
  migrated test now gets the copy's annotations it doesn't have itself, or, when the copy isn't among
  the migrated sources, a Migration Marker naming them.
- The Migration Recipes kept the explicit version of a project's `browserless-test-spring`, which wins over the
  Vaadin BOM: a project on the old standalone add-on, 1.1.2, ended up with it beside Browserless 25
  ([#354](https://github.com/parttio/unified-testing-tool/issues/354)). The Browserless, TestBench and Dramafinder
  recipes now remove it when the project's Vaadin BOM manages the version.
- The documented migration commands ran whichever OpenRewrite plugin was newest. They now name the versions the
  recipes are tested against, 6.46.1 for Maven and 7.39.0 for Gradle
  ([#355](https://github.com/parttio/unified-testing-tool/issues/355)).
- The Dramafinder recipe skipped every test class that navigated with `page.navigate(getUrl() + "/plan?week=" +
  monday)`, the usual way to open a view with query parameters: `getUrl()` was a base class member no rule
  converted ([#351](https://github.com/parttio/unified-testing-tool/issues/351)). The call now becomes
  `page.navigate("plan?week=" + monday)`, the path after the base URL, also on `getPage()` and in helpers. A class
  that uses `getUrl()` in any other way is still skipped, with its Migration Marker.

- On Playwright, `selectItem(..)`, `selectItems(..)` and `deselectItems(..)` in a field the application replaces
  as it takes the value waited 10 s and failed with Playwright's `TimeoutError`, though the change went through, as
  in the order editor of Vaadin's Bakery ([#377](https://github.com/parttio/unified-testing-tool/issues/377)). A
  field the lookup no longer finds is not checked after the change, and a multi-select combo box's drop-down is
  closed only while the field is still there.
- A pick that didn't take failed with a plain `IllegalStateException`, `"Large" could not be selected in …`, and
  a read that timed out while checking it with Playwright's `TimeoutError`. Both now fail as a
  `UnifiedAssertionError`: `Expected  item “Large” selected in combo box “Size”`, `Found` what is selected, the
  Testing Tool's own error as the cause ([#377](https://github.com/parttio/unified-testing-tool/issues/377)).
- The style rule `TOOL_CODE_NEEDS_CAPABILITY` flagged a helper called from a `tryUnwrap(..)` check, though the
  check itself was exempt ([#449](https://github.com/parttio/unified-testing-tool/issues/449)). What an optional check calls, at any depth, may now use the Testing Tool's
  types; `unwrap(..)` and an `…EscapeHatch.of(..)` are still flagged there.
- Playwright's `focus()` didn't focus an element without a Dramafinder mapping, such as one from
  `findDescendants(..)` or a `UnifiedMessageInput`: it focused the host, which never takes focus. It now focuses
  the component's focus part, as Selenium does ([#450](https://github.com/parttio/unified-testing-tool/issues/450)).
- A grid column under a header group row wasn't found by its caption, and sorting it picked the wrong header cell
  ([#338](https://github.com/parttio/unified-testing-tool/issues/338)). A column's caption is now its own header cell's text, then its groups', on every Testing Tool.
- The TestBench and Dramafinder recipes didn't add `browserless-test-spring`, so a migrated Spring Boot project
  failed at once on Browserless. They now add it, at the version the Vaadin BOM manages.
- A Migration Marker quoted the comments above the call it marked, run into the marker's text
  ([#326](https://github.com/parttio/unified-testing-tool/issues/326)). It now quotes the call alone; the comment stays above the statement.
- The Migration Recipes didn't give `page` to a helper with an overload: the second declaration dropped the first's
  calls, so a test reaching an Escape Hatch through it didn't compile ([#324](https://github.com/parttio/unified-testing-tool/issues/324)).

## Known limitations

Those of [0.1.0-alpha3](0.1.0-alpha3.md), and:

- The Browserless recipe leaves a `MockVaadin` call without a Migration Marker or `@RequiresTestingTool`; such a
  test passes on Browserless and fails in a browser ([#470](https://github.com/parttio/unified-testing-tool/issues/470)).
- The browser's console is read on Playwright and on Selenium with Chrome. Firefox on Selenium has no browser
  log, so `hasNoErrors()` checks the application's log only there. TestBench has no API for the console
  ([#316](https://github.com/parttio/unified-testing-tool/issues/316)).
- Log lines are given to a User Step by time, not by cause. With tests running in parallel in one JVM, only the
  lines a test's own thread logged are kept.
- An application that logs through a backend other than Logback or `java.util.logging`, such as Log4j 2, gets no
  server lines.
- "Scenarios without a check" takes a value read after the last action as checked; it can't see whether an
  assertion follows.
- The comparison with another Testing Tool doesn't say whether a difference is a documented Limitation
  ([#310](https://github.com/parttio/unified-testing-tool/issues/310)).
- The `write-unified-ui-tests` skill names the API reference and the Findable View but none of the other
  additions, and its evaluation was not rerun after those changes.
- The Findable View lists components grouped by Wrapper type, not in the order of the page.
